# CVM's novelty is empirical, not architectural

Almost every architectural primitive in CVM v0.1 already exists somewhere. The OS and virtual-memory framing goes back to MemGPT (2023). Runtime-owned eviction, pointer handles, Denning-style thrash metrics and provenance-checked writes all appear in ClawVM (EuroMLSys '26). Stateless-per-step operation with model-written state is MEM1's core idea. Runtime-enforced, attenuating agent capabilities are in Agent libOS and several 2026 delegation papers. Deterministic citation-existence checks have published precedents. What I found no precedent for is CVM's *measurements*. No prior work shows a live LLM keeping resident context flat (about 12 objects, about 2k tokens) while a URI-addressed world grows 1,000-fold. No prior work shows causally that model-written notes decide whether a small, runtime-owned working set is viable: without notes, 96% re-materialization and 0 accuracy; with notes, solved with 2 resident objects. CVM should therefore be positioned as an integration plus a scaling study. Its pitch would be "virtual memory for the *world*, not for the agent's own session", with ClawVM, Scroll and MEM1 cited up front as the systems it extends. It should not be pitched as a new paradigm. Three caveats limit how hard any of this can be claimed. The flat-residency result partly holds by construction. The live-model sample is small (n=15 and 30). And many 2025-2026 arXiv comparisons rest on search snippets rather than full-text reads, because arxiv.org was blocked for most of the research.

## Every CVM primitive has a named predecessor

The table below gives a verdict for each CVM claim. "Prior art" means a published system already does essentially the same thing. "Partly novel" means the mechanism exists but CVM's specific shape, or the measurement attached to it, does not. "Novel" means I found no precedent after a targeted search. Absence of evidence here is a weak negative, not proof.

The pattern is clear. The architecture column is almost entirely "prior art" or "partly novel". The genuinely open cells all sit in the empirical rows.

## ClawVM, Scroll and MEM1 each virtualize a different axis

Ten systems come closest. Each is close on a different dimension, and the cleanest way to position CVM is by *what grows* while context stays bounded.

**ClawVM is the most dangerous single competitor.** It treats "the context window [as] physical memory, durable stores [as] disk". It makes capture and recall "policy, not discretion". It defines typed pages with stable identifiers and provenance, plus a "pointer" residency level ("a resolvable handle plus minimal metadata"). It counts refetch faults and reports a thrash index adapted from Denning. It tests an LRU variant, and it rejects writeback whose `evidence_ref` dangles ([arXiv 2604.10352](https://arxiv.org/html/2604.10352)). A reviewer who knows ClawVM will see most of CVM's vocabulary already in print. The differences are still real. ClawVM virtualizes the agent's *own session state* (plans, preferences, tool outputs), not an external world graph. It budgets tokens through a knapsack policy, not an object count. Its faults are failures the harness *detects*, whereas CVM's FAULT is a legitimate model *action* whose frequency is the thrash signal. Its evaluation is offline and replay-based over 12 Claude Code traces, with live end-to-end task quality explicitly left "to future work" ([§5.2](https://arxiv.org/html/2604.10352)). CVM's live-model results fill exactly that gap.

**Scroll virtualizes session history.** It keeps "a working view over a persistent Session Environment". As the view approaches its budget, stale spans are evicted "but remain recoverable" through an eviction index of exact log addresses. It reports 73.1% on BEAM_10M and 86.7% on LOCA_256K ([arXiv 2608.21690](https://arxiv.org/abs/2608.21690), snippet only). On "bounded view + eviction + re-materialization" it overlaps CVM heavily. Its environment is the agent's own event log, accessed through model-written Python, and I could not confirm its eviction policy or whether it ever plots view size against log size.

**MEM1 bounds horizon, not world size.** The agent "learns to discard the previous context … immediately after generating a new internal state". Peak tokens stay almost constant as objectives grow from 2 to 16, and on 16-objective QA it scores 3.5x higher with 3.7x less memory than Qwen2.5-14B ([arXiv 2506.15841](https://arxiv.org/html/2506.15841v2); [GitHub](https://github.com/MIT-MI/MEM1)). This is the strongest precedent for "stateless per step plus model-written state". MEM1 learns the behavior with RL. CVM imposes it with a runtime and pairs it with a paged object view.

**MemGPT and AIOS are the ancestors, not rivals.** MemGPT's paging is self-directed ("it can decide when to move items between contexts"), and it reports only task accuracy ([arXiv 2310.08560](https://arxiv.org/html/2310.08560)). AIOS's "context switching" snapshots LLM generation state for scheduling. Its LRU-K swaps agent memory items between RAM and disk, and its evaluation measures serving throughput ([arXiv 2403.16971](https://arxiv.org/html/2403.16971)). CVM inverts MemGPT's control split and works at a different layer from AIOS.

**BM25 Wins at Scale is the methodological twin with the opposite result.** It sweeps corpus size over 28 nested tiers (about 450-fold) while holding questions fixed. Its file-system agent costs 39x more query tokens than BM25 and "becomes less effective as the search space grows". BM25 overtakes the agent around 10M corpus tokens ([arXiv 2607.26497](https://arxiv.org/html/2607.26497v3)). CVM cannot claim the fixed-task size-sweep design. It can claim that a paged agent over a *structured* world reverses that study's agent-scaling trend.

**GABench is the closest "agent on a multi-million-node graph" result.** It runs agents on 13 datasets from 26 to more than 3.7 million nodes and reports token consumption ([arXiv 2608.01684](https://arxiv.org/html/2608.01684v1)). Its tasks are whole-graph analyses whose difficulty grows with the graph. I could not confirm whether it plots tokens against node count, so it needs a PDF check. Think-on-Graph already runs bounded beam search over Freebase, reporting cost in LLM calls (at most 2ND + D + 1 per question) rather than resident context ([ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/file/10a6bdcabbd5a3d36b760daa295f63c1-Paper-Conference.pdf)). So "first LLM agent on a 1e6-scale environment" is not available as a claim.

**CaMeL and Agent libOS bracket the capability story.** CaMeL's "capabilities" are per-value provenance tags enforced by an interpreter for security ([arXiv 2503.18813](https://arxiv.org/html/2503.18813v2)). That is a different meaning from CVM's. Agent libOS is CVM's true peer on this axis. It defines an `AgentProcess` with process-local object memory, child processes and explicit, non-ambient typed capabilities, and children receive "no automatic propagation down process trees" ([arXiv 2606.03895](https://arxiv.org/html/2606.03895); [GitHub](https://github.com/yingqi-z20/Agent-libOS), README summary). CVM's verb × URI-namespace grants with subset inheritance are a specific instance of that design, not a new category.

**Citation-verification work splits the verifier's novelty.** The Anthropic Citations API guarantees "valid pointers to the provided documents" but does not reject an uncited claim ([docs](https://platform.claude.com/docs/en/build-with-claude/citations)). Citation-Grounded Code Comprehension mechanically checks that cited line ranges overlap retrieved chunks, reporting "92 percent citation accuracy with zero hallucinations" ([arXiv 2512.12117](https://arxiv.org/abs/2512.12117)). EBTE denies *actions* whose evidence claims conflict with server-held facts ([arXiv 2607.25364](https://arxiv.org/abs/2607.25364v2)). By mid-2026 a survey already treated "evidence attribution, tool-use provenance, runtime guardrails" as named threads ([arXiv 2606.04990](https://arxiv.org/abs/2606.04990)). CVM's verifier is an integration of these ideas under a page-table metaphor.

## The defensible claim rests on world-size invariance and the notes ablation

The novelty claim that survives the evidence, in two sentences:

> *CVM shows that a runtime-owned, object-count-bounded working set over a URI-addressed world keeps an LLM's resident context flat, about 12 objects and 2k tokens, while the world grows 1,000-fold, with no detectable accuracy loss for a live model, and that model-written notes are the causal ingredient that makes such a small working set viable rather than thrashing. Architecturally, its contribution is making the stable handle the single unit of paging, capability enforcement and provenance, unifying mechanisms that prior systems (ClawVM, MEM1, Agent libOS, citation verifiers) provide separately.*

This framing gains strength from three contrasts. Against ClawVM, CVM virtualizes world state rather than session state, and it adds the live-model evidence ClawVM deferred. Against MEM1, the axis of invariance is world size rather than task horizon, and the bound is enforced by the runtime rather than learned. Against BM25 Wins at Scale, the paged agent's cost stops scaling with the environment instead of growing 39x. The notes ablation is the strongest single result. ClawVM measures thrash but never ties it to a missing notes area, and VideoLoop shows rewritten bounded memory beats append-only only in a video setting without runtime LRU ([arXiv 2609.38119](https://arxiv.org/html/2609.38119v1)). I found no prior work that switches the notes off under a fixed working set and watches accuracy collapse while re-materialization climbs to 96%.

Several claims should be dropped or softened: "OS for LLMs", "first page-fault mechanism for LLMs", "first runtime-enforced agent capabilities", and "grounding prevents hallucination". The last conflicts with CVM's own result that grounded answers were still wrong. The positioning that fits best is a systems paper with a concrete experimental thesis, and venues such as EuroMLSys or the AgenticOS workshop at SOSP 2026 ([os-for-agent.github.io](https://os-for-agent.github.io/)) already host this conversation. An ML-venue submission would need the expanded experiments below.

## Reviewers will attack construction, scale and the retry loop

Most objections are predictable, and each maps to a specific experiment.

| Anticipated objection | Why it bites | Experiment that addresses it |
|---|---|---|
| **"Flat by construction."** A capped resident set is flat by definition, and the deterministic reference processor scores 1.00, so the task is algorithmically easy. | The interesting question is not whether residency is bounded but whether *accuracy* survives the bound and what drives residency. | Sweep *task* complexity (hop depth, fan-in, distractor density) at fixed world size and show residency tracks the task, not the world. Report accuracy against cap size (k = 2…32) as well as against world size. Report the virtualization ratio. |
| **Synthetic world.** The generator's topology and hubs may favor CVM. | Real graphs have heavier-tailed degree distributions and noisier text. | Rerun on a Wikidata or Freebase subgraph, on AIOps topologies ([AIOpsLab](https://arxiv.org/html/2501.06706v1), [OpenRCA](https://netman.aiops.org/wp-content/uploads/2025/05/13411_OpenRCA_Can_Large_Langua.pdf)), or on Spider 2.0 schemas ([arXiv 2411.07763](https://arxiv.org/html/2411.07763v2)), each subsampled to nested size tiers as in BM25 Wins at Scale. |
| **Small n, one model.** 0.53 at n=15 vs. 0.70 at n=30. | By my calculation the approximate 95% Wilson intervals are about 0.30-0.75 and 0.52-0.83. That supports "no detectable drop" but not invariance, and certainly not improvement. | Use n ≥ 100 per tier across at least three tiers (1e3, 1e4/1e5, 1e6), three or more models, and paired questions across tiers. Report CIs and a pre-registered equivalence margin. |
| **Missing ToG-style baseline.** A bounded beam search over the same KG might match CVM. | ToG is the canonical bounded KG explorer ([arXiv 2307.07697](https://arxiv.org/abs/2307.07697)). | Add ToG beam search, a programmatic-tool-calling or RLM-style REPL baseline ([arXiv 2512.24601](https://arxiv.org/pdf/2512.24601)), a tuned BM25 and file-system agent baseline ([arXiv 2607.26497](https://arxiv.org/html/2607.26497v3)), and, if feasible, MEM1 and Scroll. |
| **Weak RAG baselines (0.12-0.38).** These look like strawmen. | BM25 Wins at Scale shows simple lexical retrieval is strong at scale. | Tune top-k and add iterative multi-hop RAG. Report the per-query token budget alongside accuracy. |
| **Reject-and-retry rewards post-rationalized citations.** | Up to 57% of citations can be unfaithful ([arXiv 2412.18004](https://arxiv.org/pdf/2412.18004)), and correctness rewards do not fix faithfulness ([arXiv 2609.23053](https://arxiv.org/abs/2609.23053)). CVM's 18-26% rejection rate followed by acceptance after re-citing fits that pattern. | Run counterfactual faithfulness tests: delete or perturb cited facts and check whether the answer changes. Compare reject→retry, reject→abstain and reject→re-derive-from-scratch. Report how often accepted answers changed between attempts. |
| **"The model cannot evict" is asserted, not justified.** | MemGPT, VISTA and ACM give eviction to the model and report gains ([arXiv 2606.30005](https://arxiv.org/html/2606.30005), [arXiv 2607.23809](https://arxiv.org/html/2607.23809v1)). | Ablate model-directed eviction and model hints, and compare LRU against ClawVM-style utility selection under equal budgets. |
| **The capability result is anecdotal.** About 5 faults per task from one model. | Deny-compliance varies strongly by model and by signal channel ([arXiv 2606.06460](https://arxiv.org/html/2606.06460v3)). | Test richer CAPABILITY_FAULT messages (for example, listing granted namespaces) and bounded retry budgets across models. Contrast namespace scoping with an IFC-based fix for the side channel. |
| **Root-cause accuracy of 0.40 undercuts usefulness.** | Grounding does not equal correct reasoning. | Separate failures into navigation errors and inference-over-correct-evidence errors, and say so up front. |

## Several citations still need a full-text check

The research was uneven in how directly it could read sources. arxiv.org, huggingface.co and alphaxiv.org were blocked in most research sessions, so many 2025-2026 arXiv findings came from search-engine snippets of abstract or HTML pages. The LLM-OS note is the exception: it reports reading MemGPT, AIOS, ClawVM, VISTA, VideoLoop and the two surveys in full HTML text. The ClawVM comparison, the most important one, is therefore on firmer ground than the others.

The following items need PDF verification before they go into a paper:

- **Scroll.** Its eviction policy, who triggers eviction, and whether it plots view size against log size. All Scroll numbers came from snippets.
- **RLM.** Whether the root context is bounded, and the "100% on BrowseComp-Plus" figure, which comes from a secondary blog.
- **MEM1.** Exact numbers. The GitHub page was read; the arXiv numbers came via snippets.
- **GABench.** Whether it reports tokens against graph size. If it does, it is the strongest counterexample to the flat-residency claim.
- **BM25 Wins at Scale.** The exponents and the 39x figure.
- **CaMeL.** The AgentDojo attack counts, and whether it addresses sub-agents.
- **Agent libOS.** Child-capability semantics. These came from a README summary.
- **2609.14631.** Its monotonic-narrowing details.
- **ProvenanceGuard.** Whether it forces regeneration or only blocks.
- **LongCite.** Its chunk-id format, which was recalled from memory.
- **Older works recalled from memory.** Liu et al. 2023 verifiability numbers and the AttributionBench F1s were not re-fetched.

Secondary-source dependencies:

- **Letta's file LRU eviction** rests only on a DeepWiki summary ([DeepWiki](https://deepwiki.com/letta-ai/letta/2.3-tool-system)).
- **The Karpathy "LLM OS" quote** comes from secondary summaries.
- **The Anthropic Tool Search 85% figure** is a vendor claim reported second-hand.

Searches not run:

- No coverage of Memory-as-Action, Memory-R1, ACE or the OpenAI Agents SDK.
- No check of whether post-August-2026 surveys group ClawVM, VISTA and CWL as a "runtime-managed residency" category.
- No check of whether ClawVM has published live-model follow-up work. If it has, that would narrow CVM's most important differentiator.

Finally, every "Novel" verdict above means "not found in a time-limited search". Several adjacent 2026 papers (ContextPilot, Continuous Context Management, Self-Evolving Context Management Policies) surfaced only as titles and were not read.

## Conclusion

The literature moved fast between April and September 2026. ClawVM, VISTA, CWL, Scroll, Agent libOS and VideoLoop together occupy nearly all of CVM's conceptual territory. A paper written as "we introduce virtual memory for LLMs" would read as late. The same artifacts read differently once the axis is made explicit. Prior systems bound context against conversation length (MemGPT, ClawVM, CWL), against task horizon (MEM1), or against input length (RLM, Scroll). CVM is the first I found to bound it against *world size*, and to test that bound with a live model. That reframing turns the architecture from the contribution into the apparatus, and turns the scaling curve and the notes ablation into the findings.

The most valuable next step is not more mechanism. It is closing the gap between "grounded" and "correct". The verifier provably blocks unmaterialized facts but still admits wrong inferences (root-cause accuracy 0.40), and its retry loop may manufacture post-hoc citations. Two experiments would turn the paper's weakest section into a second strong finding: a faithfulness audit of retried answers, and a ToG-and-BM25 baseline run on a real graph at n ≥ 100. Together with the notes ablation, these would give CVM a claim that ClawVM, MEM1 and Scroll cannot match on their own.
